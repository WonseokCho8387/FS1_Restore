# Farland Story (한국어판 DOS/V, TGL / Sur De Wave) — Unity 이식용 에셋

`tools/` 안의 스크립트로 `CD/Farland1.cue`에서 다시 만들 수 있습니다.

```
python tools/cue_extract.py CD/Farland1.cue extracted
python tools/export_unity.py extracted/iso extracted/audio UnityAssets
```

## 원본 구성
- 16-bit DOS 실행파일(Borland C + ASM), VGA 640x480 16색 planar, 디스크 이미지는 데이터 1트랙 + CD-DA 18트랙
- 실행 순서: `FS.BAT` → mouse / mimic(PCM 드라이버) / fmp3(FM 음원) / mconf / `FSMAIN.EXE`, 오프닝은 `OP.EXE`

## 오프닝 연출 (`Opening/`)
OP.EXE의 오프닝은 스크립트 파일이 아니라 C 코드(0x2320~0x5800, 장면 함수 22개를 0x1F19가 순서대로 호출)로 하드코딩되어 있습니다.
`tools/op_emu.py`가 Unicorn으로 이 장면 함수들을 그대로 실행하면서 아래를 기록합니다.

- 스텁 처리: 파일 로드, vsync 대기, CD 음악, 화면 켬/끔. EMS(int 67h)는 최소 구현
- 원본 그대로 실행: TOY 디코드, 블릿, 팔레트 페이드, 스크롤. VGA 포트·A000 접근을 가로채 4플레인 VRAM·DAC·CRTC를 재현
- 사운드 모드는 5(CD-DA)로 고정. 이 모드에서 음악 동기 대기는 vsync 프레임 수로 동작하므로 타임라인은 60fps 프레임 단위입니다(총 6,668프레임 ≈ 111초, 음악은 CD 트랙 2)

| 파일 | 내용 |
|---|---|
| `opening_timeline.json` | `ops`: 프레임 t에 적용할 그리기 명령(`blit`/`clear`/`gem`, VRAM 바이트 주소 기준, 피치 80바이트, 64KB 랩). `states`: 변화 시점의 화면 상태 전체(표시 시작주소, 표시 줄 수 400/480, 화면 끔, 16색 팔레트 hex). `scenes`: 장면 시작 프레임 |
| `Indexed/*.bytes` | 640×400 픽셀당 1바이트 색 인덱스(GEM은 0xFF=투명). `NAME~1`은 원본 버퍼 겹침(장면당 0x1F40 단락 간격 디코드 vs 실제 0x1F68)으로 하단 8줄이 덮인 상태를 그대로 뜬 변형 |
| `opening_preview.mp4` | 타임라인을 재생해 구운 참고 영상(640×480, 60fps, track02 음악) |
| `Scripts/OpeningPlayer.cs` | Unity 재생기. `tools/op_player.py`와 같은 규칙이며, 이 규칙으로 에뮬레이터 화면과 샘플 2,182프레임이 픽셀 단위로 일치함을 확인 |

480줄 모드 장면에서 화면 하단에 보이는 잔상 줄은 원본에서도 페이지 아래 VRAM이 비치는 현상입니다.

## 본편 대화 (`Dialogue/`)
STAGExx.MSG는 FSMAIN.EXE 0xE9C0의 `talk(이벤트, 유닛0, 유닛1, …)`가 해석합니다. `#X` 블록을 찾아 줄 단위로 실행합니다.
화자 이름과 초상화는 대부분 **런타임에 넘겨받는 유닛 인자**(`*0`, `0` 등)로 정해집니다.

| 코드 | 의미 | JSON |
|---|---|---|
| `<NN` `>NN` | 왼쪽/오른쪽 초상화 FACE{NN}. `<*d`는 인자 d의 얼굴, `<`만 있으면 지움 | `portrait` side, face / arg |
| `?dm` `?df` `?dNN` `?r` | 인자 d가 남성 / 여성 / 얼굴 NN일 때만, 50% 확률. 중첩 없이 직전 조건을 대체 | `if` cond |
| `?^` `?` | 조건 반전 / 조건 해제 | `else` `endif` |
| `w` `k` | 줄 앞 `w`=창 지우기, 화자 뒤 `k`=이 줄 뒤 키 대기(페이지 끝) | clear, wait |
| `d` `/d` `.d` | 화자: 인자 d 유닛 이름 / 인자 문자열을 이름 자리에 / 인자 문자열을 회색 한 줄로 | speaker = unitName / argString / argLine |
| `q` `a` `e` | 블록 끝: 창 닫기 / 초상화 유지 / 맵 갱신 | `end` mode |

- `characters.json`: 캐릭터 이름표(FSMAIN DS:0x2CEE). 얼굴 번호 = id-1
- `talk_calls.json`: talk() 호출부 143곳. 이벤트, 인자(`unit[k]` = 유닛 배열 0x8A92+k×0x24), 스테이지, 훅
  - 스테이지 훅 테이블: DS:0x1356, 스테이지당 far 포인터 7개 × 14스테이지. 훅 이름은 호출 위치·대사로 **추정**한 것
  - 0x10BED = 1스테이지 직전 프롤로그, 0x116B8 = STAGE99 에필로그 → 음악 12 → 엔딩
  - 인자가 레지스터 값(ax, si 등)인 곳은 정적 분석으로 풀리지 않아 그대로 남겼습니다
- `Scripts/FarlandDialogue.cs`(실행기) + `FarlandDialogueView.cs`(UGUI 표시 예시)

## 엔딩 (`Ending/`)
FSMAIN.EXE 0x1114F를 `tools/fs_ending.py`로 에뮬레이션했습니다. 0x1150E가 음악 12(CD 트랙 13)를 틀고 호출하며, 끝나면 무한 대기합니다.

1. 0~864프레임: 오른쪽(x=304, 336×400)에 END1(성 탑)을 144단계×6프레임 세로 패닝하며 팔레트 페이드인
2. 864~991: 검정으로 페이드아웃 → END2(두 사람) 표시 후 페이드인
3. 1215~: 왼쪽 304px 영역에 ENDING.MSG 121줄을 줄당 40프레임(20px, 2프레임당 1px)으로 스크롤
4. 6175프레임(약 103초) 이후 정지 화면

- `ending_timeline.json`: 위 단계 + 스태프 줄별 시작 프레임
- `ending_preview.mp4`: 에뮬레이션 화면 녹화(트랙 13 음악 포함)
- 영문 폰트는 원래 설치 시 만들어지는 FS.TBR에서 EMS로 올라가는데 이 CD에는 없어서, 미리보기는 NORMAL.ENG로 대신 그렸습니다

## 전투 규칙 (`Battle/battle_data.json`, `Scripts/FarlandRules.cs`)
FSMAIN.EXE를 정적 분석한 결과입니다(괄호는 근거 코드 주소).

**유닛** — 배열 DS:0x8A92, 0x24바이트 × 62칸(0~17 아군, 18~ 적). +0x0A부터 템플릿 26바이트:
이름ID, 클래스, 레벨, 최대HP, HP, 경험치, 공격, 방어, 지식, 마법방어, 민첩, AI, 장비. 이동력 항목은 없고 모두 20입니다(0x9816).

**배치** — 스테이지 준비 훅이 0xA0B9(템플릿, 좌표목록)을 부릅니다. 스테이지 1~14, 프롤로그, 13-b(13스테이지 2차) 배치가 `stages`에 있습니다.

| 항목 | 위치 | 내용 |
|---|---|---|
| 클래스 42종 | DS:0x04BC 이름 | 3개씩 계열. 6~8 성직자·9~11 엘프·15~17 왈큐레계는 여성. 18~ 적 전용, 30~ 적 버전 인간 클래스, 60·61은 구출 NPC |
| 이동 비용 | DS:0x0E72 | 클래스 × 지형 10종, 99=불가. 예: 파이터 평지3·길2·숲4·바위6·물가10, 비행계 전부 4 |
| 지형 | DS:0x1156 / 0x1246(13스테이지) | 맵칩 120개 → 지형. 피해 배율 DS:0x04A8: 평지90·길100·숲60·바위70·마을50·물가90·성90·성문60 % |
| 아이템 79종 | DS:0x230B, 16바이트 | 가격, 물리(직접·간접), 마력(직접·간접), 플래그(직접1·간접2·특수4·회복8·고유0x10·정령0x20·전직0x40·부활0x80), 장비 마스크 |
| 성장 확률 | DS:0x651A | 플레이어 클래스 0~17 × HP·공격·방어·지식·마법방어·민첩 % |

**공격 계산** (0x17E01 → 0x2851E)
1. 물리 = 공격 + 무기물리[직접/간접] − 상대 방어, 마법 = 지식 + 무기마력 − 상대 마법방어 (각각 0 하한, 무기 값이 0이면 0)
2. 클래스 상성 보정: 방어측 기준(나이트·마법사·드워프·비행·고스트·스켈톤·서큐버스·메두사·데몬계·마왕) → 공격측 기준(성직자 마법 0, 정령 무기 능력치 약화와 마법 2배/½, 드워프 직접공격 물리 2회분, 서큐버스→남성 ×2). 전체 분기는 `FarlandRules.Matchup` 참고
3. 피해 = (물리+마법) × 방어측 지형 배율 / 100
4. 크리티컬: 민첩 차(최대 80) × 3 % 확률로 ×3
5. **명중 판정 없음**. 피해 0이면 빗나감 효과음, 피해는 상대 HP로 상한

**경험치·레벨** (0x28171, 0x27D02, 0x17352)
- 레벨 20 이상이면 경험치 없음. 적에게 준 피해만큼(처치 시 적 템플릿 경험치) 획득, 최소 1, 누적 상한 2000
- 100 단위를 넘으면 레벨업 1회: 성장 확률마다 최대HP +0~3(상한 150), 능력치 +1(클래스 번호가 3의 배수면 +0~2), 상한 45
- 아군이 쓰러지면 레벨 −1, 경험치 −100, 성장 확률마다 능력치 −1

**맵 격자** — 헥스(벽돌형)입니다. 짝수 행이 반 칸(16px) 오른쪽으로 밀린 'even-r' 오프셋이며, 방향 0~5의 이웃 규칙은 0x9A5A에 있습니다. `Maps/*_preview.png`는 이 배치로 다시 그렸고, `StageMapLoader.cs`는 Unity Hexagon 레이아웃(행 y=-(r+1), cellSize.y=4/3)으로 놓습니다.

**사거리·반격** (0xA171, 0xA39E, 0x1875C)
- 직접 공격은 거리 1, 간접 공격은 **정확히 거리 2**. 마왕은 둘 다 +1. 무기 플래그 1/2가 각 방식 사용 가능 여부
- 공격 뒤 방어측이 살아 있고, 방어측 무기가 같은 방식을 지원하면 **반격**. 같은 편 대상 행동(비숍·클레릭·프리스트 회복, 프리스트 간접, 버드 노래, 페어리 회복)은 반격 없음
- 피해는 공격 1회에 한 번 적용(0x17EFC → HP바 애니메이션 0x178D1)
- 경험치: 아군이 적을 공격해 살아남으면 준 피해만큼, 적이 공격해 아군이 반격하면 반격 피해만큼. 처치 경험치는 사망 처리(0x17574)에서. 버드(17)가 아군에게 노래하면 5

**메두사 석화** (0x288A2) — 메두사(27)·AI 2가 '시선' 연출(전투 기록 +0x26=7)로 공격하면, 메두사 킬러를 든 상대가 아닌 한 피해 = 남은 HP

**적 AI** (유닛 +0x20, 0xAA98 → `Scripts/FarlandAI.cs`)
적 턴(0xB313)은 슬롯 18~61을 차례로 돌며 비었거나 HP 0이거나 **ai 5(휴면)**이거나 이미 행동한 유닛을 건너뜁니다. 흑기사·다크 프린세스·다크 퀸·마왕(클래스 38~41)은 **한 턴에 두 번** 행동합니다. 유닛마다 스테이지 훅 4가 0xAA98(유닛, 경유지x, 경유지y)을 부릅니다. 경유지는 스테이지 대본이 하드코딩하고(없으면 −1), 가까워지면 AI 값을 바꾸는 식으로 진군을 연출합니다.
1. 이동 범위(0x9599): 이동력 20, 클래스×지형 비용. **다른 유닛 칸은 같은 편이라도 들어가거나 지나갈 수 없음**. **지배 영역**(0x9282): 출발 칸이 아닌 칸이 살아 있는 상대편 유닛과 이웃하면 그 칸에서 멈춤. 아군 이동에도 같은 루틴을 씀
2. 경유지 접근(0xA58C): 도달 칸 중 경유지와 헥스 거리가 가장 짧은 칸. 동률이면 이동 비용 싼 지형 → |x−y| 작은 칸 → 남은 이동력 많은 칸
3. 후보 수집: 자신 기준 ±20 창을 위→아래·왼→오른 순으로 훑어 마을과 유닛이 있는 칸을 **최대 9개**
4. AI 4는 도주, HP 20 미만이면 후보 중 빈 마을로, 페어리는 HP 20 미만 같은 편 치료
5. 공격 대상: 공격 위치가 있는 아군 중 가장 가까운 대상(동률이면 피해 배율 높은 지형에 선 대상)
6. 공격 위치(0xA171): 직접·간접 각각 대상 주위 링에서 피해 배율이 가장 낮은 지형(동률이면 남은 이동력 많은 칸). 반격 못 받는 방식 → 간접 쪽 지형이 더 좋으면 간접 → 직접 순
7. 이동 뒤 제자리 공격(0xA39E): 사거리 링 안에서 피해 배율이 가장 높은 지형에 선 대상(동률 50%)
- AI 값별 동작은 `aiModes` 참고(16 매복, 1·2·3 고정, 5 휴면, 6·15·18 소환, 9 아크 추적, 17 근처 아군 추적, 4 도주)

## Unity 임포트 가이드
1. `UnityAssets/` 내용을 `Assets/Farland/`에 복사
2. 모든 PNG: Texture Type=Sprite, Filter=Point, Compression=None, PPU=32
3. `SpriteDefs/*_frames.png`: Sprite Mode=Multiple → Grid By Cell Size(json의 frameWidth×frameHeight), Pivot=Custom(json의 pivotX/pivotY)
4. `Tilesets/MAPCHIP_tiles.png`: Sprite Mode=Multiple → Grid By Cell Size 32×32로 슬라이스
5. 빈 오브젝트에 Grid + Tilemap 만들고 `Scripts/StageMapLoader.cs`에 json·타일 스프라이트 배열 연결 (Grid는 스크립트가 Hexagon 레이아웃으로 바꿈)
6. 원작 해상도 640×400(PC-98 원본 기준) → Pixel Perfect Camera(Reference 640×400, PPU 32) 권장
7. 오프닝: 빈 오브젝트에 `Scripts/OpeningPlayer.cs`를 붙이고 `timelineJson`=`Opening/opening_timeline.json`, `indexedImages`=`Opening/Indexed/*.bytes` 전부, `music`=`track02` AudioSource, `target`=640×480 RawImage 연결
