# Farland Story — Unity 프로젝트

원작(파랜드 스토리 DOS/V 한국어판) 추출 데이터로 만든 Unity 2022.3 프로젝트입니다. 오프닝부터 1~14스테이지, 에필로그·엔딩까지 이어서 플레이할 수 있습니다.

- 실행: `Assets/Farland/Scenes/Main.unity` 열고 Play (씬이 없으면 메뉴 **Farland > Create Main Scene**)
- 조작: 좌클릭 선택/이동/공격, 우클릭·Esc 취소, WASD·방향키·휠 클릭 드래그 화면 이동, 휠 확대, Space 턴 종료(전투 연출 중에는 빨리 감기), B 전투 연출 켜기/끄기
- 검증: 메뉴 **Farland > Run Smoke Test** — 화면 없이 1스테이지를 자동 진행해 로그로 결과를 남깁니다

## 교체 가능한 구조

> **리소스·대사를 고치는 방법은 [리소스_수정_안내.md](리소스_수정_안내.md)** 에 정리했습니다(Tiled 맵, 캐릭터별 그림, 대사 표, 용어집).


게임 코드는 리소스를 직접 참조하지 않고, **콘텐츠 팩**의 상대 경로로만 읽습니다(`Farland.Content.ContentDB`).

```
Assets/StreamingAssets/Content/
  base/                    원작 추출 기본 팩 (priority 0)
    pack.json
    Config/game.json       시작 스테이지, 음악 파일 규칙, 적 턴 속도, 난수 시드
    Config/stages.json     스테이지 흐름: 맵·대화 파일, 음악, 이벤트(개시 대화, 보스 교전·격파, 도착 승리…)
    Config/visuals.json    타일·유닛·얼굴 그림 규칙, 글꼴, UI 색
    Config/strings.json    UI 문구 (현지화)
    Battle/battle_data.json  클래스·아이템·지형·배치·AI 데이터
    Maps/STAGExx.tmj       맵 타일(Tiled), Tilesets/*.tsj 타일셋
    Dialogue/STAGExx.json  대사(구조), STAGExx.tsv 대사 표(고친 대사), characters.json 이름표
    Characters/NN/         캐릭터별 그림(맵·얼굴·전투), Config/glossary.json 고유명사
    Sprites/*.png  Tilesets/*.png  Audio/BGM/trackNN.ogg
  example_override/        교체 예시 팩 (pack.json 의 enabled=false)
<persistentDataPath>/Mods/<팩>/   빌드 후 사용자 모드 (같은 구조)
```

**규칙: 같은 상대 경로의 파일이 여러 팩에 있으면 `priority`가 가장 높은 팩의 것을 씁니다.** 파일 단위로 덮어쓰므로 바꾸고 싶은 파일만 넣으면 됩니다. JSON도 파일 통째로 바뀌므로(항목별 병합 없음) base 파일을 복사해 고치세요.

### 교체 예
| 바꾸려는 것 | 넣을 파일(새 팩 기준) |
|---|---|
| 아크 얼굴 | `Sprites/FACE00.png` (아무 크기 PNG) |

| 맵 타일 | 낱장 `Tilesets/MAPCHIP_tiles/000.png`… (번호 = 맵칩 번호, 14장은 `MAPCHIP2_tiles`) 또는 시트(32×32, 가로 10개) |
| 1스테이지 대사 | `Dialogue/STAGE01.tsv` 의 '고친 대사' 칸(구조는 `STAGE01.json`) |
| 캐릭터 이름 | `Dialogue/characters.json` |
| 배경 음악 | `Audio/BGM/track03.ogg` 등 (음악 번호 n = 파일 번호 n+1, 규칙은 `game.json` 의 `musicFile`) |
| UI 문구·언어 | `Config/strings.json` |
| 글꼴 | `Fonts/IYG.HAN`(한글 8x4x4벌 조합형 16×16) + `Fonts/NORMAL.ENG`(영문 8×16) — `visuals.json` 의 `bitmapFont`. 원작 글꼴 파일 그대로이며 다른 .HAN/.ENG 로 바꿀 수 있다 |
| 창 그림 | `UI/window.png`(반투명), `UI/window_solid.png`, `UI/window_menu.png`(타이틀 보라) — 원작 WINCHIP/WINCHIP2 를 9조각으로 다시 짠 것. 조각 경계는 `visuals.json` 의 `windows.*.border` |
| 마우스 커서·대사 넘김 표시 | `Sprites/MCSRFONT.png` (24×24, 0 화살표·5/6 ▼) — `cursorImage` |
| 스테이지 흐름 | `Config/stages.json` — 이벤트 trigger: `start`, `turn`, `bossEngaged`, `bossDefeated`, `reach`. args: `unit:N`, `boss`, `attacker`, `defender`, `mover`, `str:문구` |
| 능력치·아이템 | `Battle/battle_data.json` |
| 전투 연출 캐릭터 | `SpriteDefs/CHAR_NN_frames.png` + `CHAR_NN.json`(프레임 크기·수·발밑 pivot). 프레임 0 대기, 1 피격, 2 쓰러짐, 3 누움. 프레임마다 낱장 `SpriteDefs/CHAR_NN_frames/000.png` 로도 고칠 수 있음 |
| 전투 배경 | `BattleMaps/BMAP_A.png` 등 (1280×240, 가운데 640 표시) |
| 전투 동작·배경 규칙 | `Config/battle_scene.json` — 클래스별 무기→연출 상태(`items`), 클립(`frames`, `hitIndex`, `run`), 지형→배경 글자, 화면 배치·속도 |

새 팩 만들기:
1. `Content/` 아래(또는 `persistentDataPath/Mods/` 아래)에 폴더를 만들고 `pack.json` 작성
   ```json
   { "id": "my_pack", "name": "내 리소스", "priority": 10, "enabled": true }
   ```
2. 바꿀 파일만 base 와 같은 상대 경로로 넣기
3. 실행 시 콘솔에 `[Farland] 콘텐츠 팩: my_pack(10), base(0)` 로 적용 순서가 나옵니다

## 리소스 수정 방법 (Unity)

리소스는 Unity 에셋(Sprite·AudioClip)으로 가져오지 않고 **실행할 때 `StreamingAssets/Content/` 의 파일을 그대로 읽습니다.** 그래서 PNG·OGG·JSON 을 아무 프로그램으로 고쳐 저장한 뒤 Play 만 다시 누르면 바로 반영됩니다(임포트 설정·재빌드 불필요. 빌드한 게임은 `Build/Win/Farland_Data/StreamingAssets/` 또는 Mods 폴더).

1. 메뉴 **Farland ▸ 리소스 ▸ 콘텐츠 폴더 열기** → `base` 팩 폴더가 열립니다(Project 창의 `Assets/StreamingAssets/Content/base` 와 같음).
2. 그림은 Aseprite·Photoshop 등 외부 편집기로 고칩니다. 도트가 번지지 않게 **원래 크기·투명 배경 그대로** 저장하세요(PNG, RGBA).
3. Unity 에서 Play → 바뀐 그림이 보입니다.

### 한 장에 묶인 스프라이트 → 낱장
여러 칸이 한 장에 묶인 시트는 **칸마다 낱장 PNG 로 나눠 두었습니다.** 게임은 낱장이 있으면 시트 대신 낱장을 씁니다.

| 시트 | 낱장 폴더 | 칸 크기 | 번호의 뜻 |
|---|---|---|---|
| `Sprites/MAPCHAR.png` | `Sprites/MAPCHAR/` (80) | 32×32 | 맵 유닛. 번호 = 클래스, +42 = 행동을 마친 회색 |
| `Sprites/ICONCHIP.png` | `Sprites/ICONCHIP/` (22) | 32×32 | 아이콘. 4 = 닫힌 상자, 6 = 열린 상자 |
| `Sprites/MCSRFONT.png` | `Sprites/MCSRFONT/` (13) | 24×24 | 0 마우스 커서, 5·6 대사 넘김 ▼ |
| `Tilesets/MAPCHIP_tiles.png` | `Tilesets/MAPCHIP_tiles/` (120) | 32×32 | 맵 지형. 번호 = 맵칩 번호(맵 JSON 의 값) |
| `Tilesets/MAPCHIP2_tiles.png` | `Tilesets/MAPCHIP2_tiles/` (120) | 32×32 | 14장 지형 |
| `SpriteDefs/CHAR_NN_frames.png` | `SpriteDefs/CHAR_NN_frames/` (47개 폴더, 713) | 클래스마다 다름(`CHAR_NN.json` 의 frameWidth×frameHeight) | 전투 연출 프레임. NN = 클래스(95~99 는 정령·이펙트), 번호 = 프레임 |

- 파일 이름은 `000.png` 처럼 세 자리 번호입니다. 완전히 빈 칸은 만들지 않았으니, 빈 번호에 그림을 넣고 싶으면 같은 크기로 새 파일을 만들면 됩니다.
- 낱장을 칸보다 크게 그려도 됩니다(같은 기준점에 맞춰 그대로 그려짐). 전투 프레임의 기준점(발밑)은 `CHAR_NN.json` 의 `pivotX`·`pivotY` 입니다.
- 마왕(`CHAR_41`)의 시트는 24960px 로 Unity 가 읽을 수 있는 최대 폭(16384px)을 넘으므로 **낱장만 쓰입니다.**
- 얼굴(`Sprites/FACE00.png`…), 타이틀(`Sprites/TITLE.png`), 전투 배경(`BattleMaps/BMAP_A.png`…), 창(`UI/*.png`)은 처음부터 한 장 한 그림입니다.

### Farland ▸ 리소스 메뉴
| 메뉴 | 하는 일 |
|---|---|
| 콘텐츠 폴더 열기 (base 팩) | 탐색기로 base 팩을 연다 |
| 사용자 모드 폴더 열기 | 빌드한 게임이 읽는 `persistentDataPath/Mods` 를 연다(없으면 만듦) |
| 스프라이트 시트 → 낱장으로 나누기 | 빠진 낱장만 만든다. **이미 있는(고친) 낱장은 건드리지 않음** |
| … 다시 나누기 (낱장 덮어씀) | 시트를 통째로 고쳤을 때. 낱장을 시트 그림으로 다시 만든다(확인 창) |
| 낱장 → 스프라이트 시트로 합치기 | 고친 낱장을 시트에 반영(시트 한 장으로 공유·보관할 때) |
| 낱장 모두 지우기 (시트만 사용) | 낱장 폴더를 지운다(확인 창) |

### 원본을 지키며 고치기(권장)
`base` 는 `tools/build_content.py` 를 다시 돌리면 CD 추출본으로 **덮어써집니다.** 오래 둘 수정은 새 팩에 넣으세요. 바꾸려는 파일만 같은 경로로 넣으면 됩니다.
```
Assets/StreamingAssets/Content/my_pack/pack.json      { "id": "my_pack", "priority": 10, "enabled": true }
Assets/StreamingAssets/Content/my_pack/Sprites/MAPCHAR/000.png   ← 아크 맵 그림만 교체
Assets/StreamingAssets/Content/my_pack/Sprites/FACE00.png        ← 아크 얼굴 교체
```
상위 팩이 시트를 통째로 바꾸면, 그보다 낮은 팩(base)의 낱장은 쓰이지 않습니다(그 팩의 시트가 이김).

## 같은 편 대상 행동 (회복·노래)

| 클래스 | 대상 | 효과 | 근거 |
|---|---|---|---|
| 비숍·클레릭·프리스트(6~8), 적 페어리(21) | HP 가 줄어든 같은 편 | **지식력 × 2** 회복(최대HP 까지). 반격·경험치 없음 | 대상 0xE0A3, 회복 0x1CBCC |
| 버드(17) | 이번 턴에 이미 행동한 같은 편 | 격려의 노래 — 대상이 **다시 행동** | 대상 0xE0B1, 효과 0xE48B |

공격 메뉴(직접·간접)의 대상 표시에 해당 동료가 함께 나오고, 고르면 전투 연출 화면에서 회복·노래 메시지와 게이지만 바뀝니다. 적 페어리는 HP 20 미만인 같은 편을 찾아가 회복합니다(기존 AI). 2장 대사 '3'(아리시아가 아크를 회복할 때 드카티가 끼어듦)과 '2'(아크가 아닌 동료는 날뛰는 드카티와 싸울 수 없음)도 이 동작에 맞춰 넣었습니다.

## 화면 구성 (원작 UI)

원작 화면 640×400 을 2배(1280×800 캔버스)로 그대로 옮겼다. 원작 DOS 판 화면과 비교해 맞춘 배치:

- **맵**: 상시 버튼·안내 없이 맵만 보인다. 유닛 오른쪽 아래에 원작처럼 작은 글자 F(아군, 파랑)·E(적, 빨강)·D(구출할 NPC, 노랑)가 붙고, 커서는 흰 모서리 틀이다(ICONCHIP 18·20·22·16, `visuals.json` 의 `sideMarks`). 유닛에 마우스를 올리면 유닛 오른쪽에 `HP/최대` 가 뜬다. 유닛을 고르면 능력치 창(공격력·방어력·지식력·민첩성·마법 방어·경험치·장비)이 화면 반대편 위에 뜬다.
- **오른쪽 클릭**: 유닛을 고른 상태면 취소, 빈 곳이면 메뉴(턴 종료·저장·조작 설명·닫기). Space·F5·F1 단축키도 그대로 쓴다.
- **명령 메뉴**: 유닛 옆에 원작 창으로 뜬다. 단계 표시(제N장·아군 턴)는 위쪽에 잠깐 보였다 사라진다.
- **대사**: 창 (66,244)~(574,352). 얼굴은 테두리 없이 창 위 좌우에, 이름은 왼쪽 칸, 대사는 「」 로 감싸 오른쪽 칸에, 오른쪽 아래에 ▼.
- **전투 연출**: 위아래로 맵이 보이는 띠(y 32~272, 흰 선) + 아래 창 세 개(왼쪽 유닛 이름·LV·HP 게이지 / 'OO에게 20 의 DAMAGE' / 오른쪽 유닛).
- **타이틀**: 타이틀 그림 위 보라색 창 메뉴(처음부터 플레이한다·게임을 로드한다·오프닝을 본다·엔딩을 본다).

## 전투 연출
교전마다 원작 전투 화면(640×400, ×2 표시)을 재생합니다. 오른쪽이 아군, 왼쪽이 적이고, 배경은 공격받는 쪽 지형을 따릅니다(평지 A, 길 B, 숲 C, 바위 D, 마을 E, 물가·물 F/G, 성 H, 14스테이지 K, 마왕전 L — FSMAIN 0x16504). 공격 쪽 클립 → (마법이면 이펙트) → 피해 시점에 상대 피격 프레임·숫자·HP 바·효과음 → 쓰러지면 2·3번 프레임. 2연타·반격은 일격마다 반복합니다.

- **상태 선택** (`classes[].rules`): 0x183AD 의 클래스별 분기를 무기·공격 방식·정령 무기·상대 편 조합마다 실제로 실행해 만든 표입니다. 예: 성직자는 아군 대상이면 회복(6), 적이면 공격(8), 엘프는 정령 무기면 소환(7), 고스트·고렘·다크 퀸·마왕은 6·7 무작위.
- **클립** (`classes[].clips`): `tools/battle_anim.py`가 클래스별 연출 함수(DS:0x61A8)를 코드 순서대로 훑어 자기 몸 프레임, 클래스 고유 이펙트(`effectFrames`·`effectAt`·`effectMove`: 기사 창 던지기, 화살, 음표, 드래곤 숨결 등), 피해 시점, 달리기, 효과음, 공용 마법을 뽑은 **정적 근사**입니다. 전투 기록을 가리키는 레지스터의 역할(자기 / 이펙트 / 그 외)을 추적해 구분합니다. 대기 프레임은 0, 피격 1, 쓰러짐 2·3입니다.
- **마법** (`spells`): 원작은 시전자 SPZ 안의 이펙트 프레임을 별도 오브젝트로 띄웁니다. 공용 루틴 5종을 옮겼습니다.
  | 이름 | 루틴 | 프레임 | 움직임 | 효과음 |
  |---|---|---|---|---|
  | fire | 0x18CFB | 4 | 날아감 | 0 |
  | ice | 0x18F63 | 5~8 순환 | 날아감 | 43 |
  | lightning | 0x191EF | 9·10 순환 | 날아감 | 44 |
  | burning | 0x19425 | 11~17 | 상대 위(2연타) | 9 (11·14번 프레임에서) |
  | firebird | 0x19615 | 18~22 발사 → 23~25 비행 | 날아감 | 43 |
  위저드 계열은 파이어 롯→fire, 아이스 롯→ice, 라이트닝→lightning, 버닝 롯→burning, 프레임 버드→firebird 입니다.
  엘프 계열 정령 무기는 (플래그>>8)-1 로 정령을 고릅니다(0x1EB2D): 라·프레아→이후리트(CHAR_98), 궁구닐→후릿가(CHAR_97), 실피드→진(CHAR_95), 타이타니아 소드→다이단(CHAR_96). 원작의 정령 연출은 팔레트·화면 효과가 섞인 긴 시퀀스라, 시전(8·9) 뒤 정령 시트 전체를 상대 위에서 재생하는 근사입니다(`spells[].sheet`).
- **효과음** (`sounds`, `hitSounds`): 원작 번호 n → 파일은 DS:0x7FD 목록 규칙(0~59 `FSEFF{n}`, 60~ `MV`, 112~ `FV`, 빠진 번호는 FSEFF00). 피격음은 0x288C3 그대로 빗나감 34, 보통 28, 크리티컬 25. 발소리 51 등은 클립의 `sounds` 에 있습니다.

교체: 클래스 그림은 `SpriteDefs/CHAR_NN_frames.png`+`.json`, 배경은 `BattleMaps/BMAP_?.png`, 효과음은 `Audio/SFX/*.wav`, 동작·마법·소리 규칙은 `Config/battle_scene.json`.

원작과 다를 수 있는 점: 프레임 간격(원작은 단계마다 대기 틱이 다름), 이펙트의 정확한 출발 위치·속도, 정령 소환의 화면 효과. 화면으로 확인한 클래스: 파이터·로드·위저드(불·버닝·불새)·기사(창 던지기)·클레릭·엘프(이후리트)·버드. MV·FV 음성은 FSMAIN 이 부르지 않아 쓰지 않습니다. 클래스 36(소녀)은 SPZ 가 없어 연출 화면에 그림이 나오지 않습니다.

## 상점·도구
이동한 뒤 행동 메뉴에 **쇼핑**(마을 칸에 멈췄고 그 마을에 판매 목록이 있을 때)과 **도구**가 나옵니다.

| 규칙 | 원작 근거 |
|---|---|
| 금은 파티 공용(DS:0x52A), 1스테이지 시작 1000, 상한 60000 | 0x10FF4, 0xBFBC |
| 소지품은 파티 공용 가방 48칸(DS:0x83BC) + 유닛마다 장비 1개(유닛 +0x22) | 0xB724 |
| 사다: 값 > 금 이면 '금이 부족합니다', 가방이 차면 '더 이상 가질 수 없습니다' | 0xCAE5 |
| 팔다: 값의 절반, 값 0 은 '팔 수 없습니다' | 0xBF4B |
| 상점에 들어가면 마을별 대화 블록(`shops[].villages[].event`)을 먼저 보여 줌 | 0xC86C |
| 도구 판정 순서: 플래그 0x80 → 옆 아군에게 사용, 4·8 → 사용(회복 = 값/2, 에릭사·환약 완전, 위스키 20 / 특수), 0x40 → 전직(레벨 10), 그 외 → 장비(지금 장비와 맞바꿈) | 0xC146 |
| 장비·전직은 아이템의 장비 클래스 마스크를 따름(예: 기사의 란스는 파이터만) | `CanEquip` |
| 마을에서 저절로 HP가 회복되지는 않음(HP 증가는 회복 아이템뿐). 마을은 지형 피해 50% | 전 코드 검색 |

판단으로 정한 것: 아이템을 **사용**하면 그 유닛의 행동이 끝나고, **장비·떼어 내기·쇼핑**은 행동을 소모하지 않습니다(원작 확인 안 됨). 0x80 아이템의 '정신차리다'는 원작에서 상태 비트를 지우는데 이 프로젝트에는 그 상태가 없어, 옆 아군을 회복하고 이미 행동한 아군이면 다시 행동할 수 있게 했습니다.

문구는 `Config/strings.json`, 판매 목록·마을 대화는 `Battle/battle_data.json`의 `shops`와 `Dialogue/STAGExx.json`, 시작 금은 `Config/stages.json`의 `startGold`에서 바꿉니다.

|---|---|---|

대사 인자: `unit:N`(아군·적 슬롯), `boss`·`attacker`·`defender`·`mover`, `str:문구`, `name:N`(이름표 id 의 이름, 예: 3스테이지 5턴째 '악마군대장').

옮긴 세부 분기: 턴 경과 대사(3스테이지 5턴째, 10스테이지 3턴째), 11스테이지 함정 연출 대사 A→B→C→D→E→F→G→O→H(`FarlandStageAI` 가 큐에 넣고 `BattleState` 가 재생), 스위치·출구 대사 I·J·K, 지형 변경(3 디노 합류, 9 (42,2)·(10,6)·(27,13), 11 (5,44)·(38,44)·(22,51), 13 (42,14)·숨은 마을 (6,6)·(17,36) 넓은 길·(18,15)·다크 프린세스 격파 통로). 지형 좌표는 `tools/stage_events.py` 가 원작 쓰기 위치와 반복문 범위에서 풀었습니다.

아직 안 옮긴 것(작은 분기): 5스테이지 특정 동료(고달·이완·윌·멜)만 하는 막다른 길·사라지는 나무 대사, 3스테이지 증원 경고 '3', 2스테이지 '3', 6스테이지 '6'·'C', 7스테이지 일반 시민 대사, 8스테이지 '3'·'4', 9스테이지 흑기사 등장 뒤 '0'~'5', 11스테이지 고렘 'L'·'M'·'N'. 13스테이지 1차(5명만 나오는 대사 장면)는 건너뛰고 2차 배치로 바로 시작합니다. 스테이지마다 있는 그 밖의 대본 이벤트(마을 방문 대사, 접촉 대사, 다리·통로 개방 외 소소한 지형 변경 등)는 전부 옮기지 않았습니다. 개발용 `-debugStage N` 은 N스테이지부터(그 앞 합류 동료 포함, 레벨은 초기값) 시작합니다.

## 세이브·로드
- 스테이지를 클리어하면(마지막 스테이지 제외) 저장 화면이 나옵니다. 15칸 중 하나를 고르거나 '저장하지 않음'.

- 원작: 설치 드라이브의 `SAVE00~14.DAT`(15칸)와 목록 `SAVEFS.IDX`. CD 의 파일은 1바이트 자리표시라 원작 형식 그대로 읽고 쓰지는 않습니다. 칸 수만 맞췄습니다.
- **전투 중 저장**: 행동이 끝나고 아군 턴에 아무것도 고르지 않은 상태에서만(교전·이동·적 턴 도중에는 불가) 오른쪽 클릭 메뉴의 **저장**, **F5**, 패드 Menu. 같은 15칸에 '제N장 (전투 중 N턴)'으로 저장되고, 이어하기로 그 턴부터 다시 시작합니다.
  - 저장 내용(`BattleSnapshot`): 턴, 곡, 모든 유닛(능력치·위치·슬롯·행동 여부·보스 교전·퇴장), 바뀐 지형 칸, 상자 상태, 이미 일어난 이벤트(`stages.json` 순서 번호)와 그룹, 스테이지 대본 상태(원작 0x84E6 플래그, 매복을 건드린 아군, 함정에 빠진 아군, 증원 신호)
  - 이벤트를 순서 번호로 남기므로 `stages.json` 의 이벤트 순서를 바꾸면 그 스테이지의 전투 중 세이브는 어긋날 수 있습니다
  - 난수 상태(`FarlandRandom`)도 함께 저장해, 불러온 뒤의 크리티컬·AI 선택이 저장 전과 같습니다

## 게임 흐름 (오프닝·프롤로그·에필로그·엔딩)
오프닝 영상 → 타이틀(처음부터 / 이어하기 / 오프닝 / 엔딩) → 프롤로그 → 1스테이지 … → `endingAfterStage`(14) 승리 → 에필로그 대사 → 엔딩 영상 → 타이틀

| 부분 | 내용 | 교체 |
|---|---|---|
| 오프닝 | OP.EXE 에뮬레이션으로 뽑은 원작 화면 녹화(음악 트랙 02 포함, 640×480) | `Movies/opening.mp4` |
| 프롤로그 | 1스테이지 맵에 프롤로그 배치(멜·훼리오·흑기사 등)를 놓고 STAGE01 대사 0·1·2 (0x10BED) | `stages.json` 의 `prologue` |
| 에필로그 | STAGE99 대사를 코드 순서로(0x116B8). `unit:N` = 동료 N번(얼굴 N). 배경 END2 | `game.json` 의 `flow.epilogue` |
| 엔딩 | FSMAIN 0x1114F 에뮬레이션 녹화(성 패닝 → 두 사람 → 스태프 롤, 음악 12 = 트랙 13) | `Movies/ending.mp4` |

영상은 클릭·Enter·Esc·Space 로 건너뜁니다. 어느 영상이든 같은 경로의 mp4(H.264/AAC 권장)를 팩에 넣으면 바뀝니다. 개발용 명령줄: `-skipOpening`, `-skipTitle`(바로 스테이지), `-debugEnding`(바로 에필로그·엔딩).

원작과 다른 점: 에필로그는 원작이 전용 맵 위에서 유닛을 움직이며 진행하지만 여기서는 배경 그림 위에 대사만 보입니다. 원작의 조건부 대사(생존 동료에 따라 갈림)는 첫 분기만 씁니다.

## 스팀덱

빌드는 1280×800 전체 화면(스팀덱 화면 그대로)으로 뜨고, 게임패드로 모두 조작할 수 있습니다.

| 버튼 | 동작 |
|---|---|
| 왼쪽 스틱·D패드 | 맵 커서 이동(칸 단위), 메뉴 고르기 |
| A | 결정(유닛 고르기·이동·공격, 메뉴, 대사 넘기기) |
| B | 취소 / 목록 닫기 |
| X | 턴 종료 |
| Y | 전투 연출 켜기·끄기 |
| LB / RB | 축소 / 확대 |
| 오른쪽 스틱 | 화면 이동 |
| Menu(≡) | 메뉴(턴 종료·저장·조작 설명) |
| View(⧉) | 조작 설명 |

- **실행 방법**: `Build/Win` 폴더를 스팀덱에 복사하고, 데스크톱 모드 Steam에서 `Farland.exe` 를 '비 Steam 게임'으로 추가한 뒤 속성 ▸ 호환성에서 Proton 을 켭니다. 게임 모드에서 바로 실행됩니다.
- **세이브 위치(Proton)**: `compatdata/<id>/pfx/drive_c/users/steamuser/AppData/LocalLow/Prototype/Farland Story/Saves`.
- **영상**: Proton 에서 오프닝·엔딩 mp4 를 못 열면 8초 뒤 자동으로 건너뜁니다.
- **리눅스 기본 빌드**: Unity 2022.3.67f2 에 Linux Build Support 모듈이 설치돼 있지 않아 아직 만들지 않았습니다. 모듈을 설치하면 같은 코드로 리눅스 빌드를 만들 수 있습니다(리눅스 판은 영상을 webm 으로 바꿔야 함).

## 아직 없는 것 · 근사로 둔 것
- **원작에서도 쓰이지 않는 대사**: 3장 'c'·'d'(밀물 이야기), 4장 'a'(숲의 정령), 11장 '1'(빈 블록)은 마을 표·대본·UI 어디에서도 부르지 않습니다(원작에 남은 데이터).
- **에필로그**: 전용 맵 연출 없이 배경 그림 + 대사로 보여 줍니다.
- **전투 연출 타이밍**: 원작은 수직 귀선(약 70Hz) 1번마다 한 틱을 돌리고 클래스별 카운터로 프레임을 넘깁니다. 클립의 프레임 순서·좌우 배치(아군 왼쪽)는 원작대로지만, 프레임당 시간(`battle_scene.json` 의 `frameTime`)은 아직 근사입니다.
- **원작 화면 자료가 없는 화면**: 상점·도구·세이브 목록, 능력치 창, 오른쪽 클릭 메뉴는 원작 창 모양으로 새로 배치했습니다.
